# Generate consistent Reference Packs before procedural modeling

Demonstration objects use the built-in image generation workflow to create project-owned raster Reference Packs, then use img2threejs to reconstruct independent code-only procedural Three.js models; generated pixels are evidence, not runtime meshes. The Reference Bible is grounded contemporary offshore research/rescue realism with graphite, warm grey, matte white, safety orange, salt-worn painted metal, rubber, composite, rope, wet concrete, and basalt, without brands or generated text. A roughly 14 m twin-propulsion hero vessel is approved first and anchors the scale for a 2.4 m buoy, 1.2 m marine crate, 8 m underwater structure, and 250–300 m basalt sea stack. Each object begins with one canonical three-quarter identity anchor, followed by an identity sheet, identity-preserving orthographic derivatives, material detail, and wet look-dev; neutral modeling references are kept separate from cinematic concept art. Every derivative repeats silhouette, part count, proportion, material, palette, and no-new-equipment invariants. Independent angle prompts, silent identity drift, and claims about hidden geometry are rejected. Approved outputs and final prompts are copied non-destructively to `assets/reference-packs/<asset-id>/v001/`, and each img2threejs state starts only after its pack is approved; generation proceeds hero vessel, buoy, crate, underwater structure, then island.
