# Use a manifest-driven startup lease

The published runtime exposes one deep startup Interface: a host calls `prepareRealWater(...)`, receives a cancellable run, and may use the returned lease only after its `ready` promise resolves; disposal is idempotent and never destroys host-owned renderer, scene, camera, or assets. The Reference Experience wraps this Interface with `startReferenceExperience(...)`, owning its DOM Loading Experience and atomic reveal. Prewarm task graphs, Three r185 workarounds, scratch compute execution, hidden RenderPipeline renders, progress accounting, and state restoration remain internal Implementation; only Loading Presenter and Host Lifecycle are public Adapter seams, while an internal Three-revision Adapter concentrates version-sensitive behavior. Runtime extension is deliberately absent in the first release: a new structural variant disposes the lease and performs a complete preparation with a new manifest hash.
