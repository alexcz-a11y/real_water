# Use a manifest-driven startup lease

The published runtime exposes one deep startup Interface: a host calls `prepareRealWater(...)`, receives a cancellable run, and may use the returned lease only after its `ready` promise resolves; disposal is idempotent and never destroys host-owned renderer, scene, camera, or assets. The Reference Experience wraps this Interface with `startReferenceExperience(...)`, owning its DOM Loading Experience and atomic reveal. Prewarm task graphs, Three r185 workarounds, scratch compute execution, hidden RenderPipeline renders, progress accounting, and state restoration remain internal Implementation. Loading Presenter and Host Lifecycle remain the top-level public Adapter seams; Host Simulation, Environment, and Presentation are typed Host Lifecycle sub-seams, and Presentation bind gives the Host scheduling authority without exposing a public `RealWaterLease.render`. An internal Three-revision Adapter concentrates version-sensitive behavior. Runtime extension is deliberately absent in the first release: a new structural variant disposes the lease and performs a complete preparation with a new manifest hash.
